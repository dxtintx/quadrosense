# QuadroSense Project Wingman Integration

Отдельный адаптер для NexusMods-пакета `QuadroSense — Project Wingman DualSense Integration`.

Поток данных:

```text
ProjectWingman-Win64-Shipping.exe -> Adapter -> QuadroSense Mod API -> DualSense
```

Адаптер читает память игры без записи и инъекции. В этой версии он рассчитывает полный
кадр эффектов и передаёт его в Mod API QuadroSense. Только QuadroSense отправляет HID.
Автоматической загрузки DLL-плагинов в приложении пока нет: адаптер запускается отдельно.

## Текущий статус

Разработка под EXE v2.1.0 с SHA-256 из manifest.json. На живом процессе найдены FNamePool,
UWorld и FlyingPawn_C. Проверены газ (+1), тормоз (-1), отпускание (0), чтение HP (97.4%)
и реакция угловой скорости на манёвр. Цепочки указателей относительны базе модуля,
поэтому учитывают ASLR. Пока не проверена устойчивость после перезапуска и смены миссии.

Цвета: полёт зелёный, меню чёрный, захват оранжевый, ракетное предупреждение красный,
потеря HP — красные вспышки 600 мс. Яркость пропорциональна HP и плавно уменьшается
при перегрузке. Перегрузка **оценочная**, рассчитывается из скорости и угловых скоростей.
R2 — газ, L2 — тормоз. Фактическое назначение кнопок задаётся в игре.
В стандартной раскладке газ/тормоз могут стоять на R1/L1: для адаптивного
сопротивления переназначить их на R2/L2 в настройках Project Wingman.

Сопротивление триггеров теперь зависит от скорости: на 150 км/ч тормоз имеет силу 2,
а газ силу 8; на 575 км/ч оба имеют силу 5; на 1000 км/ч тормоз достигает 8,
а газ снижается до 2. Между этими точками сила меняется плавно с округлением до
доступного уровня DualSense.

При взлёте и ниже 250 км/ч — лёгкая фоновая вибрация (18/5 из 255),
от 250 до 350 км/ч плавно затихает. В диапазоне 350–700 км/ч вибрации от газа
и фоновой вибрации нет. Выше 700 км/ч вибрация от газа плавно нарастает до
30/8 при 1000 км/ч и полном газе. Урон, перегрузка и торможение действуют независимо.
При нажатом тормозе и замедлении свыше
15 км/ч за секунду появляется тяжёлая вибрация, достигающая 180/75 при
замедлении от 120 км/ч за секунду. Включение сглажено за 60 мс, затухание —
250 мс. Просто удержание тормоза на постоянной скорости не создаёт тяжёлый эффект.
Урон сохраняет приоритет. После паузы и разрыва телеметрии ложного удара нет.

Захват (`t_CurrentLockedTarget` count), пауза (`g_isPaused`), оранжевый цвет и красные
вспышки при уроне подтверждены пользователем. Предупреждение (`MissileRefCollection`
count) пока кандидат: требуется входящая ракета и проверка по HUD. Гироскопическое
прицеливание отложено по пожеланию пользователя. Layout требует проверки смены миссий и перезапусков.
`m_LockedOn` исключён из источников ракетной угрозы: в тесте совпадал с собственным
захватом цели и ошибочно включал красный вместо оранжевого.

В конфиге `enabled: false`: обычный запуск завершится без подключения к игре или API.
`--live-test` разрешает ограниченный тест на 60 секунд. Для постоянного запуска после
проверки выставить `enabled: true`. Сначала запустить **обновлённый** QuadroSense/API:
этой интеграции нужно исправление TTL в ControllerOutputService из этого репозитория.
При потере процесса/ошибке чтения отправляется нейтральный кадр. При остановке адаптера
его override удаляется; при аварии срок действия кадра (250 мс) истекает на стороне API.

## Сборка

```powershell
dotnet build .\QuadroSense.ProjectWingman.csproj
dotnet run --project .\QuadroSense.ProjectWingman.csproj --no-restore -- --self-test
```

Команды собранного EXE:

- `--self-test`: проверка логики без игры и геймпада.
- `--probe`: чтение отражённых Unreal-полей процесса игры; не изменяет конфиг.
- `--telemetry`: минута вывода нормализованного состояния без управления геймпадом.
- `--live-test`: минутный тест полного пути игра → QuadroSense → DualSense.
- `--session-test`: тест на 5 минут с журналом `session-test.jsonl` возле EXE.
- `--config <путь>`: альтернативный конфиг для обычного запуска.

Root — RVA глобального указателя относительно EXE. Каждый offset означает
`address = ReadPointer(address) + offset`; конечное значение читается по полученному
адресу. Float-поля умножаются на scale. API по умолчанию http://localhost:5176.

Для публикации: `dotnet publish -c Release -r win-x64 --self-contained true`.
Архивировать publish вместе с manifest, JSON и README (копируются при сборке).
Игровые EXE/DLL в пакет не включаются. Публикацию на Nexus выполнять после проверки
всех сценариев и перезапусков; текущая версия предназначена для разработки.
